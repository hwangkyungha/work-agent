# 업무 글 작성 기준

work-agent는 사용자 PC의 스킬 설치 여부와 관계없이 같은 글쓰기 기준을 사용합니다. 모델을 호출할 때 실행 파일에 포함된 `writing-guidelines.md`를 전달합니다. 자동 브리핑처럼 저장된 제목을 그대로 표시하는 기능은 AI로 다시 쓰지 않습니다.

문장을 고칠 때는 표현과 사실을 따로 확인합니다. 문장이 자연스러워도 날짜·시간·조건·부정 표현이나 확신 정도가 바뀌면 수정본을 사용하지 않습니다. API 이름과 이슈 번호, 코드와 인용은 원래 표기를 유지합니다.

## 작성 예시

아래 예시는 문장 작성 방식을 설명하기 위한 가정입니다.

| 상황 | 원문 | 개선 예시 |
|---|---|---|
| 업무 메시지 | CT2612-486 4h 입력 완료 상태이고 Jira 등록 여부는 미확인 상태입니다. | CT2612-486에 4h를 입력했습니다. Jira 등록 여부는 확인하지 못했습니다. |
| 확인한 결함 | 날짜 전환 시 작성 내역 보존에 대한 선제적 처리가 요구됩니다. | 요일을 바꾸면 저장하지 않은 입력값이 사라집니다. 다른 날짜로 이동해도 입력값이 유지되도록 수정해 주세요. |
| 근거 부족 | 타임존 때문에 날짜가 항상 잘못됩니다. | 날짜를 계산할 때 서버의 기본 시간대를 사용합니다. 운영 서버도 한국 시간으로 실행되는지 확인이 필요합니다. |

짧은 메시지에는 문서용 목차와 반복되는 인사말을 붙이지 않습니다. 원인을 설명할 때는 조건과 결과를 함께 적고, 위험을 확인하지 못했으면 질문이나 확인할 내용으로 남깁니다.

## PR 리뷰 댓글

댓글은 발생 조건, 코드에서 확인한 동작, 사용자에게 미치는 영향과 필요한 수정을 설명합니다. 한 원인에서 나온 지적은 하나로 모읍니다. 코드와 테스트를 읽어도 결함을 입증할 수 없으면 결함 댓글로 게시하지 않습니다. 글쓰기 기준은 검토 내용이 맞는지 확인하는 절차를 대신하지 않습니다.

문장 점검 기준은 [korean-writing-qa의 검사 항목과 목적](https://github.com/kkhfiles/korean-writing-qa/blob/main/docs/check-inventory.md)도 참고했습니다. 표기 오류와 문맥 판단, 개인 문체 선호를 구분하는 방식을 반영했습니다. 특정 단어를 일괄 치환하거나 다른 조직의 문서 형식을 강제하는 검사기·훅은 설치하지 않습니다.
