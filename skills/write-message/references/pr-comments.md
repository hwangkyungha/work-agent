# PR 리뷰 댓글

독자는 코드를 고치거나 질문에 답할 작성자다.

- 확인한 결함은 발생 조건, 코드의 동작, 영향과 필요한 수정 순서로 쓴다. 같은 원인의 지적은 한 댓글로 모은다.
- 결함을 입증하지 못했으면 확인한 사실과 추가로 확인할 내용을 구분한다. 코드에 없는 동작이나 실행하지 않은 테스트 결과를 근거로 쓰지 않는다.
- 구현 방법이 여럿이면 필요한 결과를 요청한다. 한 방법만 정답처럼 제시하려면 그 제약의 근거가 있어야 한다.
- 질문에 답할 때는 질문의 조건부터 확인하고, 현재 코드로 답할 수 있는 범위와 남은 확인 사항을 구분한다.
- 게시 전에는 검토한 커밋과 줄 번호가 현재 PR에도 맞는지 확인한다. 공개 여부와 AI 표시 방식은 사용자가 정한 정책을 따른다.

## 예시

아래 예시는 가정이며 실제 결함을 뜻하지 않는다.

확인한 결함: “첫 저장 요청이 끝나기 전에 버튼을 다시 누르면 같은 워크로그가 두 건 저장됩니다. 등록 요청과 서버의 저장 결과를 확인했습니다. 요청 중에는 버튼을 비활성화하고, 서버에서도 같은 요청이 중복 처리되지 않도록 수정해 주세요.”

근거가 부족한 경우: “이 함수는 서버의 기본 시간대를 사용합니다. 운영 서버 시간대는 아직 확인하지 못했고, 날짜 오류도 재현하지 못했습니다. 운영 서버의 시간대와 자정 부근 기록을 확인해 주세요.”

문장의 자연스러움과 지적의 정확성은 따로 판단한다. 글쓰기 검사를 통과해도 결함이 입증된 것은 아니다.
