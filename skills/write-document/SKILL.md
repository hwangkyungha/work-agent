# 공유 문서 작성

독자가 자료를 이해하고 필요한 판단을 할 수 있는 문서를 작성한다.

1. 독자, 문서의 목적과 범위를 확인한다. 이미 제공된 정보로 정할 수 있으면 진행하고, 결과를 바꾸는 정보가 없을 때만 묻는다. 짧은 데일리·주간 공유는 `brief`, 회의 자료는 `meeting`, 계획은 `plan`, 비교 조사는 `research`, 승인·선택 요청은 `decision`으로 구분한다.
2. [공통 기준](../work-agent-writing/common.md)과 해당 종류의 참조만 읽는다. [짧은 공유](references/brief.md), [회의](references/meeting.md), [계획](references/plan.md), [조사](references/research.md), [의사결정](references/decision.md) 중 주된 목적 하나를 고른다. 사용자가 준 자료를 읽고, 문서에 담을 사실과 출처를 연결하면 초안을 작성한다. 자료가 없으면 임의의 결론을 만들지 않고 필요한 자료를 요청한다.
3. 초안을 공통 기준의 **원문 대조**로 확인한다. 독자가 알아야 할 결론·요청과 근거를 본문에서 찾을 수 있고, 확정 사실·제안·남은 결정이 구분되면 내용 검토를 마친다. 해당하지 않는 항목은 새로 만들지 않는다.
4. 승인·선택을 요청하는 문서이거나 여러 팀의 역할·범위가 달라지는 계획이면 [독자 검토](references/reader-check.md)를 진행한다. 짧은 현황 공유와 문장 수정은 3단계로 완료한다.

## 산출물

사용자가 요청한 형식과 길이를 따른다. 형식 지정이 없으면 Markdown으로 제공한다. 파일 저장 요청에는 프로젝트의 저장 규칙을 적용하고, 채팅 초안 요청에는 본문을 응답한다. 외부 게시와 전송은 별도의 사용자 요청에 따른다.
